## Material gaps found and resolved in this audit

`frontend/planning/timing.js` generates smooth sampled positions, velocities, and accelerations, and the exported trajectory contains those derivatives. At the start of this audit, `frontend/program-player.js` and the shared/triggered clock modules linearly interpolated positions between samples and discarded derivative fields. The parent added `frontend/timed-joints.js`: a quintic segment evaluator that matches positions, velocities, and accelerations at both endpoints. Player and both clocks preserve those arrays and use the same evaluator. I checked the coefficient formulas and C2 matching. `timing.js` now validates playback at interval quartiles for joint/velocity/acceleration limits, FK path error, collision states, and collision edges; the four-bar planner also checks passive chain-rule rates there. `tests/timed-joints.test.cjs` checks knot continuity and rendered fractional positions. This resolves the representation mismatch at the declared sampled-check level; it still does not provide a continuous mathematical collision certificate.

`AGENTS.md` says the app must continue to work without a server. All prior workcell browser tests used loopback HTTP. The separate browser audit initially found that direct `file://` startup failed on a legacy XHR for the default robot. The parent embedded that URDF and added a main-thread planner fallback. The UI initially still fetched relative classroom examples; `frontend/example-text.js` now bundles the advertised text fixtures for file origins while retaining HTTP fetch for served edits, and the Workcell/Workspace buttons use it. `tests/example-text.test.cjs` verifies the bundled inputs. The final `tests/file-launch-browser.test.cjs` opens the file URL in ordinary Chromium without special file-access flags, clicks the pick-and-place button, plans PTP/CIRC/LIN, checks actual rendered quintic interpolation, carries/releases/resets the workpiece, downloads/reopens the project, and checks no external requests or browser errors. The trace is `notes/artifacts/file_launch_default.json`. This closes the no-server first-release acceptance path.

The workcell accepts only one active URDF robot and a bounded SDF subset, and T-10 lists possible later extensions including a Python-like front end and simultaneous external axes. The original request said programming could use *either* a mini language or Python-like scripting; the existing mini language satisfies that choice. The roadmap's first-release acceptance does not require physical I/O, generic closed-loop dynamics, or arbitrary multi-robot coordination.
