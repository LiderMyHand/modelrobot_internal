# Six-axis teach pendant and inverse velocity jogging

Date: 2026-11-13. This extends the first-release workcell with interactive serial-robot Cartesian jogging. It uses the reusable `frontend/planning/velocity-ik.js` solver described in `notes/2026-11-13_velocity_ik_core.md` and the existing full-pose IK/planner for programmed moves.

## Operator controls

The **Program → Teach pendant** panel uses the selected TCP link from **Drive TCP to a pose**. Its blue virtual keypad has six paired rows. **Joint** mode maps them to J1–J6 along the selected TCP chain; **World TCP** and **Tool TCP** map them to ±X/Y/Z and ±Rx/Ry/Rz. The COORD button cycles those three modes, while the adjacent selector provides direct access. Joint speed is a percentage of the selected joint's configured velocity limit; Cartesian modes use separate linear/angular speed fields. The current TCP world pose and joint positions remain visible. **Detach panel** moves the same working keypad into a draggable, resizable floating panel so it can remain open while viewing the Workcell or other tabs; **Dock** returns it to Program. The paired-row layout was informed by the user-supplied [FANUC keypad photo](https://lobot.pl/1023-large_default/klawiatura-gne2-do-fanuc-teach-pendant-panel-operacyjny-a05b2301c335.jpg) and official manufacturer guidance archived in `notes/2026-11-13_pendant_reference.md`. It intentionally omits numeric, menu, and safety hardware keys.

A click requests one kinematic step; holding a button repeats steps after 320 ms at the selected step interval. Releasing the pointer, losing capture, blurring the window, or hiding the document stops the hold timer. **Teach TCP pose** appends a named world-frame `POSE` plus `MOVEJ`; **Teach joint pose** appends `JOINTS` plus `MOVEJ`. Both are editable DSL source and need Plan before replay.

The direct-pose panel now also exposes `world` or `tool` target frame. World means an absolute TCP target. Tool means an offset expressed at the current TCP frame at command planning time; e.g., `POSE goal tool 0.02 0 0 Q 0 0 0 1` requests +2 cm along the current tool X axis. Switching to tool resets the four pose values to zero translation and identity orientation. The planner's existing `worldPose()` composes the current tool world transform with that local target before full-pose IK or LIN generation. Tool orientation is relative and uses the same quaternion/angle-axis conventions.

## Jog step

For one button request, the UI snapshots the current serial chain and ordered joint vector, forms a TCP-origin twist with one nonzero component, and calls bounded damped inverse velocity IK. World requests use world axes; tool requests rotate the linear and angular three-vectors by the current TCP orientation. The solver returns `qdot`, achieved twist, residual, rank, and a one-step `nextQ`. A `limited` or `singular` result is reported and does not alter the joints. Velocity and position bounds use URDF limits and project overrides.

Before an accepted step is displayed, the UI checks the current and interpolated joint states against the same explicit robot/SDF collision query used by the planner, with at most 0.02 rad or 0.005 m per checked substep and a 100-step cap. It then invalidates any old motion plan without rewinding the displayed joints, applies `nextQ`, and updates the TCP/joint feedback. A blocked collision or invalid input leaves the joint state unchanged. Constrained four-bars use their independent input slider; the serial Jacobian jog does not silently break closure.

Joint-mode rows request a single-joint rate equal to the chosen percentage of its limit, integrate for the selected step duration, and use the same position and sampled collision checks. If a robot has fewer than six active joints along the selected TCP chain, the remaining rows are visibly disabled.

This pendant is a **kinematic jog simulator**. It checks each discrete step, not continuous collision freedom; it does not model motors, brakes, force contact, or acceleration ramps for manual hold. Program playback still uses separately timed, smoothed trajectories. A real robot controller needs its own safety and servo implementation.

## Evidence

`tests/velocity-ik.test.cjs` checks Jacobian mapping, world/tool twist conversion, singular and limited diagnostics, and a six-axis configuration. `tests/teach-pendant-browser.test.cjs` loads the classroom arm in Chromium, checks J1 jog, COORD mode cycling, one World +Z and one Tool +X jog, actual changed joints and TCP feedback, an invalid-speed no-change result, held-button repeat, taught pose/joint source syntax, and no browser errors. It detaches the panel, switches tabs, jogs from the floating keypad, drags it, and docks it. It also checks that manual jog takes over from a planned trajectory at a displayed midpoint without rewinding and that an added obstacle in the classroom workcell blocks a jog at an interior collision sample without changing any joint. Inspected screenshots and trace are `notes/artifacts/teach_pendant_joint.png`, `teach_pendant_detached.png`, `teach_pendant.png`, and `teach_pendant.json`. `tests/direct-pose.test.cjs` also checks a relative tool pose lands at the same world target as the corresponding absolute pose. The four-bar browser test checks that its nonserial mechanism still loads and is not broken by pendant feedback.

The final rebuilt full suite passes **220/220** in `notes/artifacts/test_full_pendant_keypad_final.log`. `npm test` caps test-file concurrency at four because unrestricted parallel Chromium sessions occasionally starved two real-time clock assertions; the two affected tests passed independently and in the final capped run. `git diff --check` passes. No changes were pushed.
