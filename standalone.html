      Enter an absolute world pose or a relative move along the current TCP axes. The solver plans a full position-and-orientation move and writes an editable one-move program.

        Command-time robot run
        Use RUN_ROBOT in a concurrent program to plan the movement source when that line is reached. A device can move first; the browser Worker then plans from the current scene and robot joints. After WAIT_SET robot_done, the program can move a device and request another robot run. Robot motion displays between logical ticks; signals and device commands commit at tick boundaries. The simulation clock pauses while planning.

        Using MyModelRobot
        
  
        Build and preview robots from URDF definitions and local STL meshes. Applied robots and their CSV animations are saved in this browser on this device.
        
  
        Your workspace
        
  
        URDF
        Edit the source, then choose Apply changes or press Ctrl / ⌘ + Enter. Applying keeps your camera, joint positions and CSV. Unapplied edits are marked above the editor.
        
  
        Files
        Open a URDF with its STL files, choose a folder, or add missing meshes later. Open saved robots, rename them, or use Save a copy for a separate version. Warning badges indicate missing meshes.
        
  
        Joints
        Drag sliders or enter values to pose the robot. Angles are in radians and sliding distances are in metres. Choose Detach panel to keep the controls visible while editing URDF or CSV. Drag its header to move, resize from the corner, or choose Dock to return it to the tab. On phones the panel stays compact; scroll inside it for more joints.
        
  
        Animation
        Paste CSV with joint names as column headers, optionally starting with time in seconds. Add current pose to CSV appends a row and creates the header only when the field is empty. Play, step between poses, add poses, or trace a link. CSV edits save automatically; invalid CSV disables playback.
        
  
        Pose tool (inverse kinematics)
        
  
        How MyModelRobot handles inverse kinematics
        
  
        The solid cyan dot marks the current centre; the hollow orange marker is its target. The dashed line shows position error, not a force or torque.
        
  
        Double-click a segment, or enable Pose tool and click one. The segment moves by its visual centre in a plane facing the camera, keeping the initial cursor offset so it does not snap when picked. Scroll or use Nearer/Farther to change its depth; click the preview again or choose Place to keep the pose. Cancel or Esc restores the starting pose; Escape again exits the tool. On touch screens, enable the tool, drag a segment, then release to place it.
        
  
        IK adjusts the selected limb’s ancestor joints within their limits, keeping its branching anchor steady. Downstream joints keep their bend angles and follow the moved segment. Revolute, continuous and prismatic joints are supported. Orientation is free; joints that cannot move the centre are left unchanged. To bend an elbow, pick its forearm rather than the casing centred on its axis. A marker and outline show the target and selected segment. Unreachable targets use a best local pose and show the remaining distance. Camera movement pauses while posing; drag empty space to orbit between selections. Playback pauses when posing starts. Collision warnings remain advisory. Use the Animation tools to capture the resulting pose in CSV.
        
  
        Collision warnings
        
  
        Enable Collisions above the preview to check shapes explicitly tagged with <collision>. Red links indicate possible overlap, and the status names the pairs. The fast check uses rotated bounding boxes, so curved and irregular shapes can give conservative warnings. Connected neighbors and fixed assemblies are ignored. Motion is never blocked.
        
  
        Choose Files → Pi collision demo to fold an arm into the torso. The Pi model includes collision shapes for its torso and complete arms. Pi robot (safe pose) restores the neutral pose. Missing collision meshes produce an incomplete-check warning; visual shapes are never used as a fallback.
        
  
        Workcell and movement program
        
  
        Open Workcell → Load pick-and-place example or Load weld-path example, then use Program → Plan path → Play. Program keeps the active robot, world, and errors at the top; expand Teach pendant, Pose target, or Advanced devices when needed. In Pose target, an absolute world pose or a relative target in the current TCP frame writes an editable one-move program. Read current TCP fills the world pose or resets tool offsets to zero. Choose PTP or a straight TCP move and quaternion or axis–angle orientation. To return later, use Workcell → Save in this browser and Open saved workcell; for a portable copy use Download project ZIP and later Open project ZIP. A ZIP carries the URDF, SDF world, local meshes, and programs. To assemble a workcell manually, open the robot URDF in Files, load its SDF world in Workcell, and edit movement in Program.
        
  
        The Teach pendant in Program has a six-row virtual jog keypad. COORD cycles Joint, World TCP, and Tool TCP modes; the selector gives direct access. Joint mode moves one axis per row at a percentage of its configured limit. World and Tool modes request TCP translation or rotation through inverse velocity kinematics. Click for one sampled-collision-checked step, or hold to repeat at the selected step duration. Detach panel keeps the keypad beside the 3D view while you switch tabs; drag its title bar and choose Dock to return it. Teach TCP/joint pose buttons append editable MOVEJ targets. Manual jog is kinematic and does not simulate a hardware enabling switch, emergency stop, or acceleration-controlled servo.
        
  
        Program lines use ROBOT name, TOOL link, named targets such as POSE p world x y z Q qx qy qz qw or POSE p world x y z AA ax ay az angle, and JOINTS name joint=value .... Motion commands are MOVEJ target, MOVEL pose, and MOVEC via_pose end_pose; GRAB object, RELEASE object, and PAUSE seconds manage the sequence. ZONE metres (0–0.2) persists until changed and requests a bounded flyby between consecutive PTP moves or through consecutive LIN/CIRC moves, including changing TCP orientation; ZONE 0 restores exact waypoint stops. WELD ON object and WELD OFF mark LIN/CIRC process paths near that object's collision surface; WELD JOIN child parent can then rigidly attach two nearby scene objects. The orange line shows the seam, and its timed path can be downloaded separately. Angles are radians, quaternion order is xyzw, and both orientation forms target the same rotation.
        
  
        Planning runs in a browser worker. PTP may route around an obstacle; LIN and CIRC preserve their requested TCP curves outside accepted local ZONE transitions and report infeasible paths. Commands stop at their boundaries by default. A positive Cartesian ZONE run keeps each circular via pose and replaces only short regions near shared waypoints with smooth position and orientation transitions. The requested radius bounds position deviation; orientation uses a separate default angular-speed cap of 1 rad/s. Blending can increase total duration. A grab requires the TCP within 4 cm of the object's collision surface, then attaches the object rigidly; release keeps its world pose. Welding requires the TCP within 4 cm of the named object's surface at sampled seam points. JOIN preserves each object's pose and makes the child follow its parent; it does not model bond strength. The blue line previews the planned TCP path. Collision checks sample the path and cannot guarantee that nothing lies between samples. This is kinematic playback, with no contact force, friction, heat, or material deformation simulation.
        
  
        Concurrent programs use separate PROGRAM name ... END blocks. Inside a block, write SET signal value, WAIT_SET signal, WAIT_UNSET signal, or WAIT_VALUE signal >= value; waits can end in an error after TIMEOUT ticks. MOVE_MODEL tray X 0.65 TICKS 4 drives a named movable SDF model to a world X coordinate in four ticks, keeping its orientation and other coordinates. Each tick's proposed device sweep is collision checked at 5 mm intervals before its pose commits; a blocked tick leaves the scene unchanged. Step to see each pose; Reset returns to the run's starting pose. The project stores program text and the scene's current pose, not a paused tick or controller state. Robot movement uses the separate motion program.
        
  
        Shared timed run: plan the robot movement program, then prepare the concurrent program with a tick duration in seconds. The robot starts at time zero; robot_done is a read-only signal that becomes set at the first tick boundary after the robot finishes. A device program can WAIT_SET robot_done before moving a scene model. Step, play, pause, and reset use one browser clock. Device motion before robot completion is rejected because planning assumed the initial scene. This is a local simulation clock, not physical controller timing or dynamic collision checking.
        
  
        Command-time robot run: in a concurrent PROGRAM, use RUN_ROBOT after device signals say the scene is ready, then WAIT_SET robot_done. You can repeat this sequence; each request replans the movement source above in the browser Worker from the current scene and joint state. The clock freezes while planning, and robot_done resets for each run. The robot is displayed smoothly between logical ticks; signals and device poses update at tick boundaries. In Workcell, Robot base frame can mount the URDF robot on a movable SDF model; a MOVE_MODEL carrier command then carries the robot before its next plan. The mount and relative offset survive ZIP export and reopen. Device motion during an active robot trajectory is rejected; simultaneous robot and device motion, physical I/O, and device acceleration control are not modeled. Reset returns to the scene before the device moved.
