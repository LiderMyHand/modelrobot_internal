# Browser planning core (2026-11-13)

This note records the first implementation of full TCP pose IK and PTP/LIN/CIRC planning in `frontend/planning/`. It is browser-compatible and does not require a server. The modules operate on plain arrays and do not mutate the viewer's robot, so a worker can receive a snapshot and return a trajectory. UI integration is a separate task.

## Current interfaces

- `createRobotModel({joints, tipLink, toolTransform, worldFromBase})` snapshots a serial URDF chain from existing `RobotJoint` objects. `forwardKinematics(model,q)` returns world TCP `{position:[x,y,z], quaternion:[x,y,z,w]}`. Active mimic joints, invalid axes and limits, and unsupported joint types fail explicitly.
- `solvePose(model,target,options)` returns `reached`, `unreachable`, `collision`, or `invalid_target`, with the best joint vector and both position and orientation residuals where applicable. Its deterministic damped least-squares solver uses the analytic world-frame Jacobian, joint-limit clamping, backtracking, and restart seeds. It verifies final forward kinematics before reporting success.
- `linearPath(start,end)` and `circularPath(start,via,end)` create TCP geometric paths. CIRC rejects duplicate/collinear points, chooses the arc through the via point (including long arcs), and interpolates orientation through the via quaternion. `solveCartesianPath` samples the geometry, includes the exact via fraction, seeds each IK solve from the prior sample, and rejects IK jumps or collisions; it does not detour a commanded LIN/CIRC.
- `createCollisionQueries(model,isStateValid,opts)` produces synchronous state and adaptively sampled edge queries. `planPTP` tries the direct edge, then seeded bidirectional RRT-Connect with collision-checked shortcutting. It supports cancellation and a time budget. The collision predicate must reflect current robot, environment, and carried-object geometry; the old throttled OBB display checker is not suitable as the planner predicate.
- `timeParameterize(jointPath,limits,opts)` creates sampled points with position, velocity and acceleration. A quintic time scale gives zero endpoint velocity and acceleration. The joint path uses cubic Hermite interpolation; it is velocity-continuous at internal knots, but acceleration may jump there. Duration is scaled and sampled results rechecked against limits. Every path knot is included, even when a requested display interval is coarse. Unsafe smoothed PTP corners can fall back to segmentwise stops, reported as `internalStops=true`.
- `planMove({type,model,start,goal,via,limits,isStateValid,options})` composes IK, geometric planning, collision queries, and timing. It returns typed failures or `status:'planned'` with `jointPath`, `duration`, and `points`. `trajectoryToROS(plan,jointNames)` exports fields shaped like `trajectory_msgs/msg/JointTrajectory` JSON, without ROS middleware.
- `parseURDFCollisionShapes(urdfXml)` extracts explicit robot collision geometry in the browser. `createPlanningCollisionScene({robotName,robotModel,allJoints,robotCollisionShapes,sceneModel,meshGeometry})` builds a detached query from robot kinematics and `SceneModel.collisionEntries`. Its `isStateValid(q)` is synchronous; `attach(name,'tool' or 'robot/<name>/link/<link>',q)` and `release(name,q)` update only the planning snapshot; `getFrameWorld(frameName,q)` resolves moving robot, tool, SDF model and model-link frames as a Three.js `Matrix4`. It uses analytic box/box, sphere/sphere, and sphere/box tests, and triangle BVHs plus containment tests for the other supported shapes. A finite SDF plane is treated as a support half-space. It excludes same or directly adjacent robot link pairs and the grasping link/neighbor pair for a carried object. Exact support contact within 1 µm is permitted, while penetration is blocked.
- `distanceToObject(name, worldPoint, q)` measures TCP proximity to a named scene object's collision geometry. It uses primitive distances or nearest BVH triangle and fails when an object has no collision shape. This supports a GRAB reach check.
- `attach(childName, 'model/<parentName>', q)` rigidly joins scene models in the detached planner while preserving the child's world transform. A joined parent can itself be attached to the robot, and nested children follow. Self/descendant cycles are rejected. Collision pairs within a joined assembly are excluded, while the assembly is checked against outside scene models and robot geometry (with the existing carrier/adjacent-link grasp exclusions). `release(childName,q)` freezes the child in world coordinates. The `SceneModel.attached` map carries this state through Worker snapshots.
- `snapshotProgramContext(context)` captures robot joint data, scene and frame transforms, collision descriptions, attachment state, and collision mesh triangle arrays into structured-clone-safe data. `planProgramFromSnapshot(compiled,snapshot)` reconstructs a detached scene and runs the same program preflight. `planProgramInWorker(compiled,context,{signal,workerUrl})` sends a one-shot request to `scripts/planning-worker.bundle.js` and returns the usual program result; abort terminates the Worker. Build this bundle from `frontend/planning/worker-entry.js` with esbuild IIFE output. The browser main thread still performs the one-time snapshot and mesh copy; collision queries, IK, PTP search, and time scaling run in the Worker.

## Limitations to resolve before claiming the full planned capability

1. The agreed architecture selected `closed-chain-ik-js/core`; that package was not installed when this core was written. The current custom DLS implementation is an interim solver behind the `solvePose` interface. Integrate and compare the external solver, including singular, limit, mimic, and 6D residual tests, before claiming that library choice is implemented.
2. The new `createPlanningCollisionScene` provides a synchronous snapshot predicate; UI preflight must build it from the current URDF and scene, then use that same query across motion and attachment commands. Do not pass the old warning-oriented, throttled `CollisionChecker` pairs to the planner. Visible URDF links without `<collision>` now stop planning explicitly. Triangle meshes are assumed closed for the containment ray test; non-watertight meshes, finite tessellation of cylinders/spheres, and the 1 µm contact tolerance can produce geometric error. Collision checking remains sampled/adaptive, not a continuous safety certificate.
3. Cartesian paths are represented as dense joint samples; cubic interpolation is checked against the commanded TCP geometry at timed samples. If it deviates, `planMove` retries with denser IK samples twice, then returns a typed error. Long or highly curved paths may need more sophisticated constrained trajectory generation.
4. Planning a PTP to a pose solves one collision-free IK configuration, not every analytic branch. Joint-space RRT-Connect is not guaranteed to find a path under a finite node/time budget.
5. UI integration must apply returned joint samples through the existing `movejoint` and verify actual joint values, because the viewer can clamp or reject a requested value.

## Verification

Run `node --test tests/planning.test.cjs tests/planning-collision.test.cjs tests/planning-worker.test.cjs`. Eighteen tests currently pass: transformed-base 6D IK; unreachable and mimic cases; LIN/CIRC geometry including long arcs and near-coincident via points; exact via sampling and blocked-path behavior; PTP detour and edge checks; timing limits and endpoint derivatives; narrow knot retention and internal-stop fallback; top-level CIRC plus trajectory export; detached robot/SDF collision, carried-object collision, support contact, adjacency exclusions, containment, STL BVH narrow phase, SDF plane penetration, grasp distance, nested welded assemblies, and structured-clone worker snapshot equivalence. The Worker entry also bundles successfully with esbuild.

The full browser suite was not used as a planning-core acceptance check while other agents were editing/running it concurrently; the root agent will run the integrated suite after all source changes settle.
