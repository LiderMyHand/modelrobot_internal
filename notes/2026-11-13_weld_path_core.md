# Kinematic weld path core

Date: 2026-11-13. The mini language now accepts `WELD ON object` and `WELD OFF`. `object` must name a loaded SDF scene model with collision geometry. The parser requires balanced ON/OFF transitions and permits only `MOVEL` and `MOVEC` motion while welding. `MOVEJ`, `GRAB`, `RELEASE`, `PAUSE`, and robot/tool changes inside that interval receive line-numbered `WELD_MOTION` diagnostics. The planner repeats the state checks on compiled input.

At `WELD ON`, the planner computes the TCP point in world coordinates and requires its **distance to the named object's collision surface** to be at most 0.040 m. It checks every timed TCP sample of each LIN/CIRC weld segment against the same object. An absent object or missing collision shape produces `WELD_OBJECT`; an excessive distance produces `WELD_DISTANCE` with the command line, measured metres, and for a segment the sample time. The distance query uses actual box/sphere/cylinder surfaces, including points inside their volumes, or nearest mesh triangles. The existing GRAB point-to-solid proximity query remains separate.

Successful `planProgram` returns `plan.weld = {segments, events}`. Each segment has `{line, type, object, startTime, endTime, samples}` where `type` is `LIN` or `CIRC`, and each sample is `{time, position:[x,y,z], quaternion:[x,y,z,w]}`. Positions are world metres, time is seconds from program start, and quaternions are xyzw. Each process event is `{time, kind, line, object, frame, pose}` with `kind` `WELD_ON` or `WELD_OFF` and the selected robot TCP frame. `plan.processTrajectory = {header:{frame_id:'world'},events,segments}` is a custom JSON process export. `plan.trajectory` remains the ROS-shaped joint trajectory; `plan.events` remains only GRAB/RELEASE for scene playback. No player modification is needed because the seam is a timed record of the already planned TCP path.

This is a geometric/process annotation. It does not model torch power, bead geometry, heat, contact forces, material removal, or rigidly attach the workpiece. The 0.040 m tolerance is a preflight gate, not proof of physical contact. Collision checking still validates sampled robot and scene geometry. Each weld seam sample is verified against the commanded object's surface after retiming, so the exported seam follows actual timed joint playback rather than only the ideal input poses.

## Runnable browser fixture

[`testowe/weld/robot.urdf`](../testowe/weld/robot.urdf) is a primitive two-axis Cartesian teaching gantry with a named `tcp_link`; [`world.sdf`](../testowe/weld/world.sdf) has a collidable static `workpiece` plate; [`program.txt`](../testowe/weld/program.txt) approaches with PTP, then runs CIRC and LIN while welding. The TCP is at z=0 and the plate top is z=-0.025 m, so the intended seam clearance is 0.025 m. The broad plate covers the entire arc and line. This simple geometry makes the process and proximity rule visible without inventing thermal behavior.

The world now also includes a separate `extension_plate` for the [post-weld joining example](2026-11-13_weld_join.md); `program.txt` remains the seam-only example.

The real Chromium Worker probe [`notes/scripts/check_weld_fixture.cjs`](scripts/check_weld_fixture.cjs) loads those files into the standalone app, plans, and captures [`notes/artifacts/weld_fixture.json`](artifacts/weld_fixture.json) plus a [browser screenshot](artifacts/weld_fixture.png). It reports PTP 0.9492 s, CIRC 2.1582 s, LIN 0.8501 s, totaling 3.9576 s and 1,300 joint samples. The weld records 940 CIRC and 299 LIN TCP samples. All seam samples are 0.025 m from the plate collision surface, with no command diagnostics, robot collision issues, or page errors. `tests/weld-fixture.test.cjs` repeats the Worker run; `tests/weld-plan.test.cjs` covers process structure, unknown/distant objects, CIRC→LIN continuity, and departure from a surface.

The fixture also exposed a general circular path timing issue: a PTP endpoint off by about 11 µm shifted the CIRC via fraction to 0.5000104, very close to uniform fraction 0.5. Keeping both as IK knots created an extremely narrow spline interval and retimed a 0.52 m arc to 980 s. `frontend/planning/paths.js` now replaces the nearby uniform knot with the exact via knot. `tests/planning.test.cjs` preserves exact via inclusion and checks that the resulting duration, sample count, joint velocity, and acceleration stay sensible.
