# Browser workcell scene and SDFormat subset

Date: 2026-11-13. This note records the scene/SDF implementation boundary for the `modelrobot_internal` workcell effort. See the project roadmap and decision ledger for overall status. The implementation is in `frontend/sdf.js` and `frontend/scene-model.js`; targeted tests are `tests/sdf.test.cjs` and `tests/scene-model.test.cjs`.

## Interfaces

`parseSDF(xml, {readInclude})` returns `{world, diagnostics}`. `world` has a name and named models. Each model has a six-value world pose, `static` flag, and named links. Each link has a model-relative pose and arrays of visuals/collisions with link-relative poses and geometry. `readInclude(uri)` is a caller-supplied, synchronous resolver for **bundled local files** and must reject ambiguous paths. Includes are expanded into inline models. Errors and warnings have `severity`, `code`, `path`, and `message`; callers should reject a world with error diagnostics before planning. `serializeSDF(world)` writes the supported subset as SDF 1.10 and throws on malformed shapes. The reader accepts version labels 1.8–1.12.

`new SceneModel({scene, meshGeometry})` creates a separate SDF environment layer under an existing Three.js scene. `loadWorld(world)` validates the object graph, builds the visual scene, and returns local asset diagnostics. `addRobot(name, root, {links})` registers an externally owned robot root and a `Map` of named link objects; it does not call the legacy `newRobot()` path. `getFrame(name)` returns the Three.js `Object3D` for `world`, `model/<name>`, `model/<name>/link/<link>`, `robot/<name>`, or `robot/<name>/link/<link>`. Call `updateWorldMatrix(true,false)` before reading its `matrixWorld`. `attach(objectName, frameName, {keepWorldPose:true})` and `release(objectName)` use Three.js reparenting that preserves the current world transform. `collisionEntries` holds shape data and a posed `frame` object for each environment collision shape. `snapshotWorld()` updates model world poses for SDF export; `attachmentRecords()` must be stored separately in the project manifest because SDF export does not represent runtime grabs.

## Supported SDF subset and limits

- One `<world>` with inline `<model>` or bundled `<include>`; world/model/link names must be unique.
- Model and link poses with `x y z roll pitch yaw` in metres and radians. `relative_to` is supported only when it names the immediate parent (`world` for models, model name or `__model__` for links, link name or `__link__` for shapes). Other frame references produce `UNSUPPORTED_FRAME`; arbitrary SDF frame graphs and cycles are not implemented.
- Visual/collision box, sphere, cylinder, plane, and local STL mesh geometry. The scene builder renders visuals and retains collision geometry descriptors. Missing local meshes produce asset errors. External URL schemes and traversal paths are rejected.
- A model with dynamic SDF semantics is loaded as a kinematic object with `PHYSICS_IGNORED`. Plugins, world physics, joints, nested models, and other unsupported content are diagnosed. The loader does not simulate forces, contacts, sensors, or welding.

The browser tests round-trip a world with a bundled include and confirm unsupported-frame/geometry diagnostics. The scene tests attach and release a part under a rotated robot frame, check collision descriptors and missing mesh errors, and check attachment cycle rejection. These tests do not yet establish integrated UI behavior or planner collision accuracy; those are workcell integration tasks.

## Bundled fixture

`testowe/workcell/world.sdf` is a four-object, local-asset-free classroom workcell for browser smoke tests. In metres, its table top spans approximately X = 0.10–1.10, Y = −0.30–0.30, with top surface Z = 0.725. The amber `pick_box` is centred at (0.42, 0.16, 0.765), the red `obstacle` at (0.64, 0, 0.805), and the green `destination` pad at (0.84, −0.16, 0.735). All four objects have explicit visual and collision geometry. `pick_box` is marked dynamic in SDF so it can be picked, but the browser currently treats it kinematically and emits `PHYSICS_IGNORED`. `tests/sdf.test.cjs` checks that the fixture parses without error, exposes all four collision shapes, and round-trips through the supported SDF serializer.

`testowe/workcell/arm.urdf` is a companion primitive-only 6R serial arm with 8 links (including fixed `tcp_link`) and explicit collision geometry on every link. Its base is at the world origin, and zero joint values put the TCP at (0.94, 0, 0.95) with identity orientation, above the table. The verified TCP targets differ from the initial design points; see [`testowe/workcell/program.txt`](../testowe/workcell/program.txt) and the [browser program evidence](2026-11-13_workcell_demo_program.md). The SDF test file checks the URDF structure, six movable joints, named TCP and zero-pose coordinates.
